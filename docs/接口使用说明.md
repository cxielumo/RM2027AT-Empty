# 接口使用说明

面向 Application 层调用者。本文按当前 `Bsp/Inc` 与 `Components/Inc` 公共头文件说明可调用的接口；它是使用指南，不替代[API设计说明](API设计说明.md)中的设计约定。接口存在不代表硬件已验证。当前未声称工程已构建或完成板级验证。

## 1. 启动与用户入口

生成的 `main()` 先配置系统时钟、NVIC、GPIO、ADC、CAN、PWM 定时器以及 USART6 DMA；随后按顺序执行：

1. `bsp_init()`：初始化 PWM、LED、CAN、UART、ADC。不可恢复错误会直接调用 `panic()`。
2. `wk_usart6_init()`：在 UART 静态帧队列建好后启用 USART6 接收。
3. `main()` 直接依次调用 `motor_tt_init()`、`servo_init()`、`dbus_init()` 初始化组件。
4. 由 `main()` 用静态栈/TCB 创建唯一默认应用入口 `robot_main(void *args)`，最后启动调度器。

`main()` 创建任务创建失败调用 `panic(FAULT_INIT)`；调度器启动后若异常返回则由封装调用 `panic(FAULT_SCHEDULER)`。在 `robot_main` 中只编写机器人应用逻辑；不要再次初始化这些模块。组件可能有自己的静态任务（DBUS），并非每个组件都需要应用创建线程。

```c
void robot_main(void *args)
{
    dbus_snapshot_t remote;
    (void)args;

    for (;;) {
        if (dbus_get_snapshot(&remote) &&
            remote.valid && remote.online) {
            /* 在此处理业务；目前 motor_tt / servo 尚未就绪。 */
        }
        os_delay(10U);
    }
}
```

`os_createTask()` 是 Application 可用的动态线程创建接口；BSP/Components 内部任务使用静态资源。`os_delay(ms)`、`os_now_ms()` 和 `os_delay_until(&last_wake, period_ms)` 以毫秒为单位；`os_task_wait(timeout_ms)` 等待任务通知，`OS_WAIT_FOREVER` 表示无限等待。线程优先级常量为 `OS_TASK_PRIORITY_LOW/NORMAL/HIGH`。不要在 ISR 中调用普通任务接口；ISR 通知使用 `os_task_notify_from_isr()` 并按需调用 `os_yield_from_isr()`。

## 2. DBUS 快照

`dbus_get(&out)` 返回一致拷贝，不暴露内部状态。调用前由 `main()` 完成 `dbus_init()`；输出参数不能为空。返回 `0` 表示查询成功，`-1` 表示查询失败；成功后还要检查 `valid` 与 `online`。从未收到有效帧时 `valid=false`；超过 100 ms 未收到有效 DBUS 帧时查询结果会令 `online=false`，最后一次有效字段仍保留，不能当作新鲜输入继续控制。

- `channel_raw[0..3]` 是中心化原始通道，`channel[0..3]` 经过死区处理并限于 `[-1,1]`。
- 开关值为 `DBUS_SWITCH_UP/MIDDLE/DOWN`；未识别值是 `DBUS_SWITCH_UNKNOWN`。
- `timestamp_ms` 是接收帧的时刻；`sequence` 每次有效更新递增。
- 鼠标、按键、拨轮字段来自同一个 18 字节有效帧。

DBUS 任务仅接受长度为 18 且无 UART 错误标记的帧；协议字段非法的帧不更新快照。
DBUS 初始化配置非法或通道归一化计算出现非有限结果时会调用 `panic(FAULT_ASSERT)`，该路径会停机并关闭 PWM 输出。

## 3. 执行器当前状态

六路 `motor_tt` 与六路 `servo` 的 API 已有声明，但当前配置没有电机驱动真值表、换向安全规则及舵机脉宽/角度校准：

- `motor_tt_init()`、`servo_init()` 可完成禁用状态初始化；`motor_tt_enable()` / `motor_tt_set_duty()` 和 `servo_enable()` / `servo_set_pulse_us()` / `servo_set_angle_deg()` 在当前未配置情况下调用被忽略。这些调用当前不会驱动硬件。
- `motor_tt_stop(id)` 用于停止单路电机；`motor_tt_get_state(id, &out)` 查询逻辑状态。占空比输入将来要求有限且位于 `[-1,1]`，但当前电机不可用。
- `servo_disable(id)` 可请求关闭已初始化的通道；查询用 `servo_get_state(id, &out)`。角度单位是度，脉宽单位是微秒；当前标定全未设置，因此不可启用或设定输出。
- `motor_dji_init()` 对空设备表正常返回；当前没有已配置电机 ID，`motor_dji_get_snapshot/enable/stop/set_raw_current` 对任意 ID 查询返回 `-1`，控制请求被忽略。不要根据型号枚举推断 CAN 协议或设备清单。

仅在硬件标定与驱动规则落实并经检查后，再在业务代码中调用执行器使能接口。不要通过绕过组件直接改 PWM 来驱动电机或舵机。

## 4. BSP 常用接口

### CAN

`can_send(bus, &frame)` 发送标准/扩展数据帧或远程帧，DLC 为 0..8；标准 ID 不超过 `0x7FF`，扩展 ID 不超过 `0x1FFFFFFF`。它只尝试投递到硬件邮箱，不等待发送完成；无空邮箱资源忙时直接忽略。`can_receive(bus, &out)` 是非阻塞接收：无帧或接收错误时返回 `-1`，有帧时返回 `0`。总线参数为 `CAN_BUS_1` 或 `CAN_BUS_2`。CAN RX 时间戳单位 ms。

### UART

当前仅 UART_6 可收帧（USART6，DBUS）；UART_1/ UART_7 调用被忽略。`uart_receive_frame(UART_6, &frame, timeout_ms)` 按 IDLE 帧边界接收，成功返回 `0`，无帧、非法参数或超时返回 `-1`。超时单位 ms，`0` 表示立即检查，`UINT32_MAX` 可无限等待（须调度器运行）。`uart_frame_t` 含最多 64 字节、长度、接收时间戳和错误位。错误位可为 `UART_ERROR_PARITY/FRAMING/OVERRUN/OVERFLOW`；应用应丢弃带错误的帧。

`uart_read()` 当前没有实现字节流读取，USART6 返回 `0`；`uart_write()` 当前未实现，USART6 返回 `0`。

### LED、ADC、PWM 与 BSP 状态

- `led_set(LED_1..LED_3, on)` 控制三颗红色 LED；编号与板上顺序相同，`true` 点亮。初始化前调用被忽略。
- `adc_sample(&sample, timeout_ms)` 读取 PA2 / ADC 通道 2 的一次转换。超时单位 ms，必须为正值且从调度器运行的任务调用；输出包含 `raw`、`full_scale`（4095）及采样时间戳。超时/转换重叠时超时或转换忙时返回 `-1`，成功返回 `0`。
- `pwm_set_duty()` 当前仅允许 `PWM_SERVO_1..PWM_SERVO_6`，占空比为 `[0,1]`；所有 PWM 按板级映射初始化；当前上层电机和舵机组件保持禁用。不要用 PWM API 绕开安全校准。
- `bsp_init()` 初始化板级驱动；固定引脚和定时器映射由驱动内部管理。`panic(reason)` 关闭全局中断、强制 PWM 输出低、关闭三颗 LED 并永久停机，只用于不可恢复的初始化/断言/栈溢出/调度器/硬件故障路径。

## 5. 错误处理

框架不定义统一状态码。可恢复的无效参数、模块未就绪、资源忙、队列为空、超时和未实现操作直接忽略；有结果的接口返回 `int`：成功为 `0`、失败为 `-1`；谓词接口使用 `bool`。UART 字节接口返回实际字节数（当前未实现时为 `0`）。应用按需检查查询结果，并避免使用过期输入。

不可恢复的初始化配置错误、静态资源分配失败、内部状态不一致、断言、栈溢出、调度器故障和硬件故障直接调用 `panic(reason)`，关闭 PWM 并停机。有限超时参数以 ms 计；`uint32_t` 时间戳可能回绕，应采用无符号差值计算间隔。输入丢失、离线或超时时，应用应按控制策略停止相关输出；DBUS 恢复后不会自动重新使能电机。
